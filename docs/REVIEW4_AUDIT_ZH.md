## 1. 总体判断

核心思路是清晰且有研究价值的：固定 Protein/RNA 双骨架，先学习各自的结构先验，再通过全局 C、局部 DeltaC 和多邻居 alpha 表达跨分子选择。这比单纯增加一个不透明交互网络更容易提出可证伪的问题。

但目前不能认定“已达到优于同行且工程完善”的状态。原因不是创新点不够，而是三个层面尚未完全对齐：第一，PDF 与代码已形成不同版本的科学协议；第二，有真实的指标、可见信息与低层 API 一致性问题；第三，实验清单虽然丰富，却不等于每项都有可执行产物，更不等于已经证明生成的两条链相容并具有功能。

最合理的定位是：**值得继续推进的机制型 mini-pilot，需要完成强基线、全链路证据与真实数据验收，不能提前写成 SOTA 或完成实验的论文。**

## 2. PDF 与实现的关键差异

完整逐项表见 `MANUSCRIPT_IMPLEMENTATION_MAP.md`，这里解释重要性。

### 2.1 结构先验实际包含同链序列上下文

PDF 的公式 6/7 容易被理解为几何编码后直接输出 logits。源码中还有 `SparseSequenceContextDecoder`，它读取本链已经可见的 token。这个设计本身合理，但论文必须区分纯几何 hidden state 与带同链上下文的 decoder state。跨分子 q 必须读取前者，而不是悄悄吸收当前 partner 序列的表示。

同时，多层同链图网络可能通过两跳路径把一个位置自身的已知 token 传回。因而“双方全部 known 后重新打分”不能直接作为无泄漏似然。新评分工具对被评分位置隐藏自身 token，并明确命名为 LOO compatibility；另提供严格的指定顺序自回归评分。

### 2.2 双中心化不是这里完全无损的规范选择

原稿要求 C 和 DeltaC 在训练中双中心化；当前源码仅减去全矩阵均值，保留行、列主效应。冻结结构先验时，给某一氨基酸整行加值会改变蛋白预测；给某一碱基整列加值会改变 RNA 预测。因此不能说双中心化只是删除了对双向任务都无影响的自由度。

本次保留全局均值中心化，补充明确的分解：全局均值、氨基酸行主效应、碱基列主效应、双中心化交互项。但这也意味着“加 C 后变好”可能只是学到了界面组成偏好，未必证明了特异的氨基酸—碱基配对信息。需要 main-effects-only 对照，以及单独报告 interaction-only 部分。

### 2.3 六阶段训练已经采用比原稿更隔离的协议

原稿在 alpha 阶段允许 DeltaC 继续更新，joint 阶段允许 C 以很小学习率变化；仓库较新的高层 orchestration 已改为 alpha 阶段只学 relevance，joint 保持 C 冻结。这可以作为提高解释清晰度的有意修订，不能被悄悄描述成原稿原本如此。

本轮还发现低层 `set_trainable_stage` 与高层入口不一致，低层 alpha 仍开放 Delta/q，低层 joint 仍开放 C。现已统一。要特别说明：这是低层 API 的修复，不能据此倒推“原来的默认高层训练一定训练错了”。scratch 对照仍需显式从 step 0 开放全部随机参数。

### 2.4 必须区分三种界面用途

第一，canonical 6 Å 全重原子界面可用于训练分组和客观评估。第二，中性骨架 8 Å 加邻居上限图用于模型感受野。第三，生成时哪些位置允许 SPIR 重开，必须来自部署时可获得的信息。

旧 sampler 直接依据 `graph.interface` 选择 SPIR 位置；真实 loader 若将它覆盖为天然侧链/碱基全原子的 canonical 标签，推理决策就依赖了固定骨架任务本来不提供的信息。这种问题不会靠“node features 不读碱基原子”自动消失。

本次主 SPIR 使用中性 PR 图的 design-interface；旧 canonical 选择保留为显式 `canonical_legacy` 消融。canonical 标签仍可用于结果分层。这个修改会改变候选序列，属于科学协议修订，不是纯粹加速，必须冻结版本后重新比较。

### 2.5 共享 C 不自动定义唯一的无序联合分布

蛋白方向和 RNA 方向分别归一化 alpha，通常产生不同的边系数。因此不能仅凭共享 C 就声称两个条件分布天然是一套无向联合能量模型的条件分布。当前方法完全可以保留：每个指定顺序都定义一个合法的自回归分布，再研究顺序敏感性。

但必须分开四个量：指定顺序的全序列 log probability、多个顺序的平均评分、有限顺序混合分布的 log probability、LOO 相容性分数。混合分布需要对全序列 log probability 做带权 logsumexp，不能把平均 NLL 当成混合 NLL。新工具把这些名称与算法分开了。

## 3. 这次确认并修复的实现问题

### 3.1 Brier 指标被错误命名

原 `brier_multiclass` 实际计算 `(max_probability - correct)^2`，这是 top-label 二分类置信度分数，并非多分类 Brier。真正的多分类 Brier 需要全部类别概率，计算各类别平方误差之和。

交付的可重现反例中，四类均匀预测的正确多分类分数是 0.75；旧函数在 argmax 恰好正确的例子里给出 0.5625。蛋白二十类也存在差异。现提供正确实现并保留明确命名的 top-label 工具。旧三标量调用被显式拒绝，不能假装仅靠已有 native/max 概率能恢复正确指标。

**交付包当时尚未完成的部分：**完整 evaluation runner 未获取，所有下游概率导出和调用点不能在离线包阶段宣称迁移完成。当前完整 checkout 已补齐 runner 的概率向量导出与校准调用，并通过静态检查和全仓 pytest；真实数据端到端指标仍需另行执行。

### 3.2 统计检验、重复样本与缺失目标

旧配对 bootstrap 使用重采样分布落在零两侧的比例充当 p 值。在五个完全一致的负差值反例中，它给出 0；在明确的符号可交换零假设下，精确双侧符号翻转给出 0.0625。新实现把效应区间与零假设检验分开，并明确检验假设；Monte Carlo p 值采用加一校正。

旧配对函数还会通过 `dropna` 悄悄缩小目标集。现在缺失、重复和非有限结果直接报错。不能把某个方法在困难目标上失败解释为“双方可比目标自动变少”。应先定义 intended pool、合法 intersection 和失败处理规则。

新五假设分析器要求完整 sample/seed/component 表，先在同一 complex 内平均训练 seeds，再在预声明独立组内平均，最后按组等权推断。H2 要同时胜过 partner-blind 和 geometry-only，使用两者 p 值最大值形成联合判定，再对五个主要假设做 Holm。组等权是一个新的明确 estimand，不能在看到原 complex 等权结果不好后才换用。

### 3.3 推理重复计算与状态边界

旧解码每个 token 都重新编码不变的骨架与跨分子几何。本次增加调用范围内的缓存，只保存几何 hidden states、q/C/DeltaC/alpha 等序列无关内容；每步仍重新计算同链 token context 和可见 partner 的校正项。检测模型或几何变化，避免陈旧缓存；恢复调用前各模块 train/eval 状态。

对自定义 forward、子类、顶层 forward hooks 自动退回完整路径，避免加速绕过内部对照模型的语义。测试验证缓存与非缓存结果一致、不会把未知 token 读进来。这里只证明软件等价与减少重复工作，没有实际 GPU 加速比例或生物设计效果数据。

### 3.4 其他可靠性补强

增加 PR 张量维度、索引类型、设备、范围和可选非有限检查；拒绝非法温度、候选数量和 refinement 次数；记录生成顺序与未经温度修改的模型 log probability；零温度确定性采样的采样概率与模型概率明确分开。模型 state_dict 键名和参数形状在验证架构上保持一致。

## 4. 与同行相比，应该怎样评价

独立阅读的主要来源与输入公平性表见 `RELATED_WORK_AND_FAIRNESS.md`。重要修正是：**NA-MPNN 本身支持保留蛋白作为上下文的 RNA inverse folding。** 之前“NA-MPNN 不看蛋白”只适用于这个仓库选择的 partner-hidden 单链参考路线，不能概括该方法的能力。

蛋白方向应考虑 LigandMPNN 的核苷酸原子上下文设计能力；RNA 方向需要含蛋白上下文的 NA-MPNN 设计模型。gRNAde 的多构象建模与 RNA 表示、RhoDesign 的结构与功能验证也提醒我们：不能把 recovery 当成全部设计质量。RNAFlow、MMDiff、RFDpoly 的任务范围不完全相同，适合界定研究版图，不应硬塞进不公平的固定双骨架排名。

建议分三条比较路线：相同小数据、随机初始化的结构先验比较；尽可能信息匹配的 partner-aware 条件设计比较；单列的公开权重实用性能比较。每条路线写清训练数据、目标/partner 原子视图、序列可见性、候选预算、计算成本和交集覆盖率。没有真实 benchmark 前，既不能保证超过同行，也不能因模型小而否定它的可解释机制价值。

## 5. 实验是否足够丰富、能否证明全链路

丰富程度已经足够，当前主要缺口不是再加十个实验名，而是补足以下因果与比较逻辑：

**C 的收益必须排除界面主效应。** 冻结 prior、C-only、main-effects-only、interaction-only 和完整 C 的比较，回答的不是同一个问题。仅有 C 与 PMI 热图相关不能证明超出组成偏好的配对规律。

**DeltaC 与 alpha 必须分别隔离。** 比较不同训练阶段的 checkpoint 只能展示学习轨迹；要证明架构模块，需要同数据、相近容量与训练机会的重新训练对照。固定距离 alpha 对 learned alpha 的对比，比仅删除高 alpha 边更关键。

**局部响应不等于正确机制。** 显式局部图本来就容易产生局部 KL 响应；较大权重的边被删后更敏感也部分来自公式本身。需要匹配距离/度数/组成的反事实、正确与错误 partner 对照，以及有标签时的突变方向或补偿性救援证据。

**联合设计必须评价配对而非两条链各自好。** 除条件设计与顺序稳定性，还需要设计蛋白配天然 RNA、天然蛋白配设计 RNA、联合设计配对、匹配的交叉错配等对照。结构验证要分别报告两条链质量和相对界面姿态；独立对齐各链可能掩盖错误 docking。

**SPIR 必须收益与多样性并报。** 同一批初始候选进行无修正、一次和多次修正，保留修改前后序列、固定位置检查、候选相似度和两链同时通过率。排名成功率要有随机挑选与固定候选集合的 oracle 上界，不能用天然序列恢复率给最终设计暗中排序。

**三 seed 与主要假设预算要一致。** 如果 H4/H5 被列为主要假设，就不能一边宣称全三 seed 主分析，一边只在单 seed 的诊断层执行它们。算力不足应在 final100 解盲前调整协议，不应事后挑最有利 seed。

细化的端点、负方向效应定义、输入 CSV、独立组统计、失败规则及全链路模块矩阵都已写入 `EXPERIMENT_VALIDATION_V2.md`。它们仍是待正式冻结并执行的协议，不是本轮已经测得的科学结论。
